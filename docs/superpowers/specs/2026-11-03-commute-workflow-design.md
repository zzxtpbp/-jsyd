# 通勤计算接入层
沿用用户已确认的四项范围：统一入口、最终缺口说明、独立场景页、串联测试。仅新增文件，不修改现有页面、API、调度及已有五模块。

输入：完整毫秒时间戳、基础闹钟归属、设置、天气触发结果与真实有效期、路线耗时与真实有效期。天气触发政策由既有业务提供，本层不另设概率/实况/预警规则，也不伪造 TTL。

计算：先检查设置时间关系；天气独立验证，固定模式无需路线。智能消费天气与路线有效期交集。合并后生成保存建议，不执行保存。诊断以最终建议或明确保留的已有较早闹钟重新计算缺口，区分建议和已保存状态。未知/无效输入明确降级，保留基础及已有记录。

演示页：ES module + 原生表单，无新增依赖，无存储/通知/音频权限、无真实接口请求，始终显示模拟数据。固定虚拟日期及时区，以可复现的状态覆盖失败与边界。
