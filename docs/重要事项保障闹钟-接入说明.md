# 重要事项保障闹钟

用户确认的规则：正常音量持续响铃，走路期间不降音量，步数达标后正常结束。此模式由用户对单条重要事项闹钟主动开启。

## 本轮交付

- `src/importantAlarm.js`：独立纯状态模块；默认20步，自定义1到200整数步。目标在开始后冻结。
- `tests/importantAlarm.test.js`：10项状态测试；`tests/importantAlarmUi.test.js`：3项控制器事件回归。
- `tools/important-alarm-lab.html`及`.js`：模拟计步、真实网页前台声音。按钮模拟步数不代表硬件检测。
- `tools/build-important-alarm.mjs`：打包单文件HTML，使用已有Vite，无新依赖。

此分支基于main 683e283，和PR #2、#3没有代码依赖；只新增文件，原页面、原闹钟和原API不修改。

## 如何体验

```sh
npm ci
python3 -m http.server 8766 --bind 127.0.0.1
# 访问 http://127.0.0.1:8766/tools/important-alarm-lab.html
# 或打包成可直接打开的文件：
node tools/build-important-alarm.mjs /tmp/important-alarm.html
```

开始按钮明确标注有声音。默认20步，可先改成3步体验；只统计本次开始后的模拟步数。走路过程中声音保持同一模式和音量包络。关闭、贪睡不会结束任务；达标后结束本次声音。

应急停止需按住8秒，松开后再确认。提前松开、失焦或取消会作废授权；未达标步事件不打断连续长按。应急停止记录为manual_exit，不能冒充步数完成。

## 接口

```js
const prepared = createImportantAlarm({
  alarmId, targetSteps: 20,
  sensorAvailable: true, permissionGranted: true,
});
// 必须先检查prepared.ok；硬件或权限未就绪时state为null。
const next = transitionImportantAlarm(prepared.state, {
  type: 'ring', sessionId, at: now,
}, now);
```

事件包括：

- `ring`：仅armed状态可开始；由调度器为每次响铃创建新sessionId。
- `step`：携带本次sessionId、严格递增的正整数sequence、发生时间at，每个有效事件只加一步。忽略旧会话、重复、乱序、未来时间及响铃前事件。
- `dismiss / snooze / lower_volume`：任务未达标时拒绝，audio保持normal。
- `exit_hold_start / exit_hold_release / exit_cancel / exit_confirm`：连续8秒长按后还需要确认；最终为manual_exit。

输出包含`ok / state / message`。即使ok为false，调用方也应采用返回的state，例如提前松开会清空长按授权。状态不会原地修改输入。

## 安卓适配层还要做什么

1. 调度、声音播放、稳定会话ID和恢复记录属于原生端；纯函数本身不响铃、不持久化、不安排闹钟。
2. 读取设备计步硬件和活动识别权限的真实状态，不可照抄模拟页的两个true。
3. 优先接逐步事件。仅将本次响铃后的真实步事件转为step；原始事件重复处理必须复用同一sequence，而非每次重放都分配新序号。计步来源不是网页任意按钮或外部可控消息。
4. 如使用累计计步器，先取得本次任务起点，处理数据延迟、设备重启和计数回退，不能用全天累计值直接抵扣目标。
5. 适配层校验传感器单调时间并转换到统一时间轴；系统时钟调整不能被当成连续长按已完成。真实长按持续时间应使用原生单调时钟。
6. 恢复任务保留已确认步数与去重序号；长按和待确认状态恢复时应清理，不能拿旧授权直接退出。
7. 音频服务消费state.audio，normal必须保持用户预设正常音量，不因计步主动降低。完成或manual_exit才结束本次播放，不影响其他独立闹钟。
8. 原生端需重新验证锁屏、后台、省电、杀进程、重启、音频焦点和系统停止。不能承诺系统层绝对无法关闭。

计步只能证明检测到活动，不能证明人已清醒；也不声称防作弊。前端纯状态对象不是可信硬件凭证。

## 验收边界

本轮真实浏览器验证：前台音频进入running；普通关闭/贪睡未结束；模拟步数去重；3步达标后停止；控制台无错误。音量未做声压测量，安卓计步未接入。

应急8秒、步事件与长按共存、失焦、页面离开后的声音恢复入口及连续提交锁有自动回归。真实BFCache与不同手机浏览器的恢复仍需单独验收。

网页不防刷新或关闭。页面离开时停止本页音频，返回后如任务尚未完成，显示实际声音状态并提供用户点击恢复入口；不能把无声任务继续写成正常播放。

计步只在内存中模拟，不请求活动权限、不读取健康平台、不上传步数。
