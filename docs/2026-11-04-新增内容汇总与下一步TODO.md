## 二、11月3日新增：通勤计算接入层

### 1. 统一计算入口

新增`src/commuteWorkflow.js`，串起：

设置时间关系检查 → 天气/路线有效期检查 → 固定/智能分别计算 → 选择较早有效时间 → 生成保存操作建议 → 输出最终诊断。

- 固定提前只依赖有效天气，不要求高德路线先成功。
- 智能提前使用天气和路线有效期的交集；未知、过期或未来更新时间不冒充有效数据。
- 不自行编造概率触发政策或数据TTL；接入方必须提供统一天气结论及真实有效期。
- 保留基础闹钟，已有更早的同次提前记录不被延后。
- 函数只返回建议，没有实际持久化、系统闹钟写入或设备同步。

### 2. 最终通勤缺口说明

新增`src/commuteSummary.js`。

- 选中固定模式后，仍按最终时间重算通勤缺口。
- 保留已有更早闹钟时，按实际保留时间重算。
- 仅匹配同计划、同基础闹钟、同次日期的唯一有效旧记录。
- 区分suggested与existing_record；都不冒充设备已经收到闹钟。
- 数据不足时缺口为null，不能显示成“0分钟、肯定来得及”。

例：基础07:00，通勤倒推需06:10；固定提前30分钟得到06:30。选中了06:30之后，仍明确提示“还差20分钟”。

### 3. 交互验收台

新增`tools/commute-lab.html`、`tools/commute-lab.js`，并提供单文件构建脚本`tools/build-commute-lab.mjs`。

- 共8场景：双模式固定取早、固定60分钟、路线失败、天气未知、天气未触发、天气过期、仅智能、复查冲突。
- 可修改提前分钟、上限、准备时间、余量、复查时间和环境音时间偏移。
- 展示候选结果、最终缺口、操作建议、事件顺序及JSON。
- 固定虚拟时钟，全部输入模拟；不保存、不通知、不播放声音。
- 单文件HTML无需安装即可体验；源码HTML需要静态服务器或开发服务器。

### 4. 测试与修复

新增15项工作流测试、8项场景断言，共23项。该分支全仓106项通过，生产构建通过。

独立审查及回归修复包括：清空复查时间报错、无新候选时漏展示有效旧铃、空记录异常、空ID误认其他记录。

浏览器已验证8场景、自定义参数、错误恢复；390px与1100px宽度无横向溢出。这是浏览器与响应式验收，不是安卓真机验收。

## 三、11月4日新增：重要事项步数保障闹钟

### 1. 用户确认的行为

- 对单条重要事项闹钟主动开启，默认目标20步，本版支持1至200整数步。
- 响铃后才开始累计本次步数；开始后冻结目标。
- 未达标期间正常音量响铃，走路过程中不降音量。
- 普通关闭、贪睡、降音量操作不能结束步数任务。
- 达标后正常结束本次响铃，记录completed / steps。
- 连续长按8秒再确认可应急停止，记录manual_exit，不冒充步数达标。

### 2. 独立状态模块

新增`src/importantAlarm.js`。

- 检查设备计步能力和授权状态；不可用则拒绝启用保障模式。
- 隔离每次sessionId，处理严格递增步事件序号；重复、旧会话、未来或乱序事件不计入。
- 每个接受事件只增加一步，不拿全天累计步数抵扣。
- 不原地修改输入，不读取传感器、不播放声音、不保存任务。
- 原生计步事件必须来自可信适配层；状态机不提供防作弊或硬件认证保证。

### 3. 模拟计步与真实前台声音

新增`tools/important-alarm-lab.html`、`.js`和单文件构建脚本`tools/build-important-alarm.mjs`。

- 网页有声音，步数由明确标注的模拟按钮提供。
- 可测试普通关闭、贪睡、重复步事件和应急退出。
- 页面离开或声音中断后，如任务仍进行，显示真实音频状态并提供点击恢复入口。
- 计步与应急长按可以同时发生；未达标步事件不打断长按。
- 按钮失焦或丢失指针捕获会取消长按；连续提交不能创建两套音频。

### 4. 测试与边界

新增10项状态测试、3项控制器事件回归，共13项。此分支全仓28项通过，生产构建通过。

浏览器以3步任务实测：普通关闭/贪睡未结束，重复事件无效，达到3步后声音停止，控制台无错误。没有测量声压，没有接真实安卓计步，没有完成锁屏/后台/强制停止验收。
